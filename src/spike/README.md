# 手记翻页 spike（StPageFlip）— 仅验证，未接入

本地打开方式：`npm run dev` 后访问 `/spike.html`。不被 `src/App.tsx` 引用，
也不在生产构建入口内（`vite build` 只打包根 `index.html`）。

## 结论：NO-GO（保留现有手记列表，不以翻页替换）

实测依据（2026-10-02，无头 Chromium 桌面 1280 / 手机 390）：

- 桌面手感与卖相成立：硬封面、纸纹页、翻页弯曲+阴影，静止页是 DOM 文字、清晰可读。
- 手机端双页模式会溢出裁切；小屏强制 `usePortrait` 单页后可用（已验证）。
- 放弃替换的决定性原因：
  1. 手记是动态数据（线索随时由「未发现」变「已记」），StPageFlip 需重初始化整本书，
     会丢失阅读位置；现有列表 + auto-animate 天然增量更新。
  2. 固定页盒装不下变长文本：现线索最长 57 字尚可，但内容深化后文本变长会被裁切，
     违反「关键剧情不得静默裁掉」的仓库规则；列表则自然流动，也尊重浏览器字号缩放。
  3. 可访问性需另备纯文本版（3D 变换块对屏幕阅读器不友好、翻页中文字为 canvas 栅格），
     等于长期维护两套实现；`prefers-reduced-motion` 用户最终也应回到列表。
  4. 手记是游戏中途反复打开查阅的工具，全量扫描效率高于逐页翻。

保留价值：若将来做「开场翻开手记」之类一次性仪式感场景，本 spike 可直接作参考实现。
`page-flip` 因此只作 devDependency，不进入生产包。
