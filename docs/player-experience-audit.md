# 《归灯》玩家体验审计与验收表

本表用来判断一次构建是否真的有“沿连云老街查明错名旧案”的完整体验，而不只是 12 张氛围图。所有剧情屏都是单屏界面；滚轮不负责章节切换。每次发行前由体验审计者按本文从头走完一遍，保存浏览器、设备、分辨率、提交号、结局和缺陷复现记录。

## 一、发版门槛

以下任一项失败，不能标记体验验收通过：

- 12 个屏幕均能从路线模型和章节清单进入；民俗资料卡不设剧情解锁门槛；没有循环软锁，重访章节不清除已取得线索。
- 12 章的时间、人物、探索操作、线索、下一步动机和结局因果互相对应；两个结局可到达且表达清楚。
- 首屏不会未经点击播放音频；点击“举灯入巷”后才能启用声景，页面常驻静音和音量控制。
- 关键谜题与追逐线索有视觉/文字替代；关闭声音或使用单声道仍能完成。
- 1440×900 和 390×844 下都不出现页面滚轮才能看见的主要内容、操作控件或退出入口；小屏用分页、局部面板或列表，不把整页压缩。
- 键盘可完成所有操作；焦点清楚，不存在只用颜色表达线索或正确/错误。
- prefers-reduced-motion 打开后没有闪烁、强烈镜头晃动、自动追镜和必须依靠动画才能看懂的状态。
- 来源卡将史料事实、地方实践、作品分析和创作转译分开；无未核实的民俗/地点断言，无伪古籍/伪地图。

## 二、逐屏内容与功能审计

每章用同一记录模板，并将屏幕截图、关键素材版本和体验者意见附在审计记录里：

| 检查项 | 通过条件 |
| --- | --- |
| 章节身份 | 站号、标题和路线地点一致；上一章留下的 NPC/物件变化能在当前章看见。 |
| 剧情推进 | 说明这一屏新增了什么信息、改变了谁的目标、为何需要玩家操作；没有纯展示但没有叙事后果的关卡。 |
| 操作目标 | 首次进入时，玩家可在 5 秒内指出可做的主要动作；主要按钮、危险状态和退出路线可见。 |
| 线索 | 取得后进入线索本并跨章节保留；返回旧章不重复发奖或覆盖新状态。 |
| 史料 | 本屏每条事实均能回到登记的原典版本/篇目或可靠机构页面；找不到来源时标为创作转译，不显示事实口吻。 |
| 视听 | 当前声源/画面异常有具体功能；静音时有字幕、方向标或文字提示，不因关闭声音卡关。 |
| 屏幕适配 | 关键人物/线索不被移动端裁切；可点区域至少 44×44 CSS px；正文通过内部分页阅读。 |
| 状态与返回 | 当前选择、线索、谜题和结局状态保存；可从路线地图到任意已开放或可访问站点并安全返回。 |

逐站额外检查：
01 点击拆信/举灯是第一次音频许可动作，齐叔、于婶和小佟都像是叫出沈归，但声源与说话人不一致；02 旧书摊确实引出《聊斋志异·尸变》，版本与篇目范围可查看；03 笔仙过程每次完成或退出都可见线索状态，并能看出它呈现的是旧错读而非替代账簿成因；04 红嫁衣、顾秋禾姓名、母亲照片和“沈｜归家”能建立连续关系；05 石街红白队伍各自有方向和姓名，且“红白双煞”明确为故事街坊临时用语；06 纸扎铺旧名册能让玩家核对顾秋禾、陆守成两条被雨洗淡的姓名，以及沈映禾写下姓名和“带沈归归家”后被梁叔誊错的过程；07 尸体追逐中的闪身、压门或绕路都有反馈，且不让听力成为唯一条件；08 戏台声源位置有字幕/可视化，台本错名可读；09 胶片可用键盘逐格浏览，并明确呈现八岁沈归落水、沈映禾救他后被潮水带走及她留下客簿去向；10 街机三乘三回环有有效退回路径、不软锁；11 梁叔交代误抄经过，客簿、名册与存档可对齐，黑白无常核名规则可理解；12 三人姓名与去向均归位后，送母亲离开和母亲离开后接灯守巷两路都能完成并可重新游玩。

## 三、空间导航与 Three.js 操作

| 场景 | 桌面验收 | 手机/降级验收 |
| --- | --- | --- |
| 3D 街区进入 | 3D 街区载入后能用拖动旋转、滚轮缩放；转场光标不误触其它控件；每个热点鼠标悬停/焦点时显示站号和可访问名称。 | 单指旋转、双指缩放，热点至少 44×44 px；另有单屏或分页的**路线清单**作为非滚轮章节导航，路线清单本身不要求滚动。 |
| 章节跳转 | 12 个热点均指向正确站点；点击热点后镜头/页面状态和进度同步。键盘可 Tab 遍历，Enter/Space 进入，方向键移动相邻热点。 | 章节名始终完整，视图切换时不会把唯一入口藏进 hover；触屏路线清单可通过单屏网格或分页直达 12 站，不要求滚动。 |
| 界面滚轮 | 章节屏默认固定视口。普通滚轮不会翻章；仅地图打开且指针位于 3D 画布时缩放模型。输入框、资料卡和滑块拦截各自操作，不触发外层导航。 | 页面和正文面板均不依赖滚动；较长内容分成有上一页/下一页的屏内分页。 |
| WebGL/网络失败 | 关闭 WebGL、拦截模型文件或加载超时后，显示相同地点的静态图与路线清单，不出现空白画布或无法关闭的加载层。 | 低内存/低速网络下可以关闭环境粒子和高分辨阴影；章节文本、线索与两结局仍可达。 |

## 四、心理恐怖节奏审计

体验者应记录“最不安时刻”和“真正理解线索的时刻”，检查恐惧是否随故事原因变化。期望节奏如下：

1. **01–03 错认建立：**声源少、事件小；NPC 站位或笔迹不合逻辑，玩家先怀疑自己是否看错。
2. **04–06 私密升级：**熟悉家庭空间、婚衣与名册将异常连到母亲；朱红仅在关键物件上出现，不能连续三屏整页染红。
3. **07 明确威胁峰值：**无名尸逼近，给出清楚躲藏/绕行选择；紧迫感高，但操作目标清楚，不靠突然全屏闪白或爆音。
4. **08–10 延迟和反复：**戏台声音、胶片多格、街巷回环依次修改前面线索；追逐后给静默段，不让玩家疲劳。
5. **11–12 解释与代价：**核名规则揭示母亲代名原因；两个结局都保留情绪代价和不确定，不突然把鬼怪解释成“其实只是误会”。

审计问题：至少有三个相互呼应的具体细节（门牌/脚步/称呼/空位等）；至少有一次前置声音在之后被重新解释；主要反转在玩家已有线索后可回想验证；NPC 重现时至少发生一个可见变化。还需确认因果线索足以复原“2006年落水救援—母亲登记姓名与归家去向—暴雨模糊字迹—梁叔合并两栏—2026年返巷核名”的完整链条，不能把笔仙写成错簿的历史成因，也不能把母亲写成最后守在客簿里的亡者。若恐怖只来自滤镜、阴影和字体，判为失败；若恐惧依靠对真实习俗的贬低、刻板民族/地域形象或未经核实的仪式细节，判为失败。

## 五、声音与动态效果

- 首次加载没有任何可听音频；“举灯入巷”点击后，才启动环境底噪和当前章声景。切章时不叠出两份环境循环；静音状态跨章保留。
- 控件支持键盘、触摸和屏幕阅读器名称。旁白/人声提供准确字幕，方向性声音有视觉方向提示，全部关键线索能静音完成。
- 音量滑块初始处于较低可辨状态；主母带无削波，true peak 不高于 −1 dBTP。避免把短促惊吓声比环境底噪突然提高超过 6 dB；不以超低频、左右耳极端摆位或爆音制造强制惊吓。
- sound event 可在偏好设置关闭；不能要求佩戴耳机，不能用响度惩罚静音用户。字幕包含说话内容和必要的声源说明。
- 关闭动态效果后禁用强闪烁、快速缩放和摇晃，保留淡入淡出所需的基本状态变化；关键剧情不得只在一帧动画中出现。

## 六、无障碍、设备与视觉检查

- 键盘全流程：Tab/Shift+Tab 顺序跟随当前场景；焦点对比度清晰；Enter/Space 激活；Escape 关闭浮层；方向键用于当前游戏/热点组件并能返回页面。
- 颜色和文字：普通文本符合 WCAG AA 对比目标；红/白、成功/失败和路线状态同时有图标或文字标志；支持浏览器缩放，不能依赖细微纹理辨认必需线索。
- 1440×900：检查全屏裁切、标题与人物焦点冲突、浮层不遮住唯一线索；全场景不会滚轮误切。
- 390×844：检查安全区、字体可读、字幕不覆盖交互、横向布局转换和触控范围；没有悬停才能发现的热点；过长内容可分页。
- 3D 模型、图像、音频按需加载；低性能设备关闭粒子/高阶后处理后仍可玩。记录启动屏、首个可操作场景与每章第一次显示的等待时间。
- 至少用 Chromium 桌面、WebKit/Safari 类移动环境各跑一遍；验证窄屏横竖方向变化后仍可返回主导航。

## 七、测试路径与缺陷等级

**完整路径：**初次访问（未点击前静音）→ 进入 01 拆信并辨认三个互相错位的叫名声源 → 02 读旧书摊残页 → 03 完成笔仙复原并区分线索与错簿成因 → 04 对照红嫁衣与母亲照片 → 05 比较红白两列脚印 → 06 从名册核对两名死者姓名空栏和母亲登记的姓名/去向 → 07 完成尸体追逐并检查白袖 → 08 静音与非静音分别辨认戏台声源 → 09 键盘逐格查看沈归落水、母亲救子后失踪及客簿去向 → 10 完成三乘三回环街机路线 → 11 听梁叔交代误抄并对齐照片、存档、名册，完成黑白无常核名 → 12 写回三人姓名与去向，分别走完“归灯”和“留灯守巷”两个结局 → 重玩并确认状态清理策略。

**重访路径：**从 09 返回 03，再从地图直达 11；已获得的线索还在，不重置剧情变量，不因切章多叠一条音轨。
**故障路径：**禁用 WebGL、断开网络、静音、关闭动态效果、连续点击热点、旋转和缩放到边界、重置本地存档；均不得卡死或丢掉结束权。

- **P0，阻断：**章节进不去/软锁、关键线索或结局不可达、未经点击自动播放、移动端无导航、静音后谜题不可解、内容引用无出处且被标成史实。
- **P1，发布前修复：**核心交互没有键盘路径、焦点被遮挡、移动端重要文本被裁切、存档覆盖、声音过响、模型加载失败后空白、叙事前后矛盾。
- **P2，可排期：**不影响理解和完成的动画帧率、装饰布局差异、轻微裁切或非关键素材一致性。

## 八、审计记录

每轮记录：日期、版本/commit、构建号、审计者、浏览器和系统、视口、声音状态、减少动态设置、章节/结局、通过项、缺陷等级、复现步骤、截图与修复版本。回归只复查修改涉及的章节和通用壳层；重大故事/模型/音频调整后重跑完整路径。
