# 仓库管理与发布规则

本文件定义《归灯》应用的目录边界、变更流程和部署责任。玩家体验的视觉与交互验收以 [`player-experience-audit.md`](player-experience-audit.md) 为准；本文件只规定如何记录和执行，不重复定义审计分数或阈值。

## 目录与内容来源

完成架构迁移后的目录职责如下：

| 路径 | 管理内容 |
| --- | --- |
| `src/` | React 页面、可复用组件、3D 场景、输入、声音、存档与故事运行逻辑 |
| `story/` | Ink 源章节、章节 ID 与逐章来源登记；作为剧情唯一源头 |
| `novel/` | 从 Ink 源导出的连续主线和备选结局，不手工维护独立剧情副本 |
| `docs/research/` | 典籍、地方实践、地点、游戏/影视与声音设计的考据记录 |
| `docs/` | 玩家体验审计、架构决策和仓库管理说明 |
| `design/references/` | 逐界面网页参考图；每个界面一张独立横图 |
| `design/prompts/` | 生图提示词及与参考图/目标素材的对应关系 |
| `design/generated-source/` | 生成的高分辨率源图及可编辑母版 |
| `public/assets/` | 经审核、供生产页面直接加载的图像、GLB 模型、字体和音频 |
| `dist/` | Vite 每次构建生成的部署目录，不手工编辑、不放源码 |

迁移期间保留当前可运行版本和用户已有素材；只有确认新路径、引用、来源和授权都完成后，才在独立 PR 中清理旧文件。移动素材时保留可追溯的来源记录。

## 史料与素材登记

- 每个章节 ID 应能映射到来源登记条目。条目记录原典/资料题名、版本或机构、篇目/页码/时间码、地域和年代（已知时）、URL、支撑的具体剧情元素，以及改编差异。
- 研究记录标记“典籍记载”“地方实践”“作品分析”或“创作转译”。当来源只支持灵感，不支持故事事件本身时，明确写出这一边界。
- 每个生产素材在 `public/assets/ASSET-SOURCES.md` 建立一条记录，字段至少为：资产路径、用途/章节、来源类别（ImageGen/自制/第三方）、生成工具与模型（适用时）、生成日期、提示词文件或原始来源链接、参考资产、后期修改、许可/署名状态及审核人。第三方资产记录适用许可链接；不明授权标记为未批准并禁止发布。
- 参考图可以含有生成错误文字或虚构地名；页面文字、古籍引用、地图和器物说明必须来自审核过的文本资料。原始提示词与生成母版保存在 `design/`，生产压缩版存于 `public/assets/`。
- 依赖和素材应使用满足用途的最小许可/权利范围；不复制游戏、电影或小说的可识别资产、受版权保护长文和音轨。

## 分支、审查与版本

- 主分支保持可构建、可预览、可发布；日常开发使用 `codex/<type>-<short-name>` 短期分支，通过 PR 合并。项目维护者负责保护主分支并要求 CI 通过与人工审查。
- 一个 PR 聚焦一个用户可感知的变化或一组紧密相关的内容更新。剧情 PR 同时更新来源登记和导出的小说；素材 PR 同时提交元数据；界面 PR 按玩家体验审计附桌面和移动端证据。
- 提交使用 `<type>(<scope>): <简短说明>`。合并前检查差异不含密钥、个人配置、临时文件或无法追溯的素材。
- 发布版本使用语义版本号；仅内容/素材变更可递增 patch，新增完整章节或交互递增 minor，破坏性内容格式或运行方式变更递增 major。发布说明列出章节/体验变化、来源或素材变化及已知限制。

## 构建与资源管理

- `src/` 是应用源码，`public/assets/` 是生产静态资源，`dist/` 是 Vite 输出。所有 `dist/` 文件由 `npm run build` 生成，默认不纳入版本控制；CI 产物及 Cloudflare 部署使用同一构建结果。
- 禁止提交 `node_modules/`、本地环境文件、密钥、缓存和临时导出。提交 3D 模型前检查文件体积与移动端加载；可压缩的图像/音频以质量可接受的发布格式输出，源文件和提示词仍可追溯。
- 删除或替换已发布资源前，搜索仓库中所有引用，并通过构建与资源完整性检查。不得仅因构建产物过期而手工修补 `dist/`。
- CI 至少运行类型检查、自动化测试、来源与 Ink/小说一致性检查以及生产构建；具体体验检查按 `docs/player-experience-audit.md` 执行。PR 不得用本地截图代替 CI 结果。

## Cloudflare Pages 责任边界

- 仓库维护 Pages 所需的可复现构建配置：安装依赖、运行 `npm run build`，发布目录为 `dist/`。项目级构建设置与仓库脚本保持一致。
- GitHub PR 使用 Pages Preview 部署供审查；只有经审查且 CI 全绿的主分支更新可以进入生产部署。发布负责人核对线上首页、12 个章节入口、静态资源、声音控制与移动端入口，并在 PR/发布记录中留部署 URL 与结果。
- Cloudflare 账户、Pages 项目创建、域名绑定、账户权限及令牌属于平台账户管理，由具备相应权限的维护者配置。令牌仅保存在 Cloudflare/GitHub 的加密密钥设置，不写入源码、日志或文档。
- 本项目是静态前端，不把 Cloudflare Pages 视为数据库或游戏后端；若将来引入服务端能力，必须另行记录数据种类、权限、隐私与部署职责后再提交。
- 生产部署异常由发布负责人先依据 Pages 构建/运行日志定位；确认是仓库变更造成时回退对应 PR 或发布上一稳定构建，并创建修复 PR。不要直接在 Cloudflare 控制台做无法回溯的代码修补。
